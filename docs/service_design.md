# 서비스 설계: 변동성 보조 지표 기반 LLM 위험 판단 (MVP)

> 서비스 트랙(브랜치 `llm-agent`) 설계 문서. 2026-10-15 작성(요청 S172~S179 논의 정리).
> 할 일 순서는 루트 `process.md`, 요청별 진행은 루트 `state.md`에 있다. 이 문서는 "어떻게 만들 것인가"와 그 근거만 담는다.

## 1. 목적과 범위

- README §2 장기 비전의 원래 목표를 MVP로 구현한다. 가격·뉴스 맥락·과거 유사 흐름을 함께 읽고, 연구 트랙의 변동성 예측을 **보조 지표**로 써서 하방 위험을 먼저 통제하는 판단(**유지 / 축소 / 관망**)을 낸다.
- 방향(매수·매도) 예측은 하지 않는다. 연구 20번에서 방향 예측력이 0에 가까웠다.
- 페이퍼 트레이딩(판단 기록)까지만 한다. 실제 주문은 범위 밖이다.

## 3. 전체 구조

```
[0 환경]  DB 링크(읽기 전용) · llm_agent.db 스키마 · LLM 실행기 · 자원 확인
   │
[1 데이터]  시세(원본 DB 조회) · 뉴스 수집(contexts/text_context.py) · 유사 흐름 마트(marts/historical_flow.py)
   │
[2 보조 지표]  TimesFM 로그 RV 분위수 · GARCH-t · 사전 국면 · 가격 정지 비율  → 지표 스냅숏(JSON)
   │            └ (라우터 자리: 국면·구간 → 모델 설정 테이블, MVP에서는 비활성)
[3 맥락]  최근 뉴스 묶음 · 유사 과거 구간 상위 k개와 그 뒤 실현 변동성·최대 낙폭
   │
[4 판단]  ① 결정: 유지/축소/관망 확률  →  ② 설명: 근거 문장
   │
[5 기록]  입력·출력·모델 버전·시각을 llm_agent.db 판단 로그에 저장, main.py가 진입점
```

## 4. 사전 국면(실시간 국면 구분)

- **정의**: 직전 H분 실현 변동성(RV)을 그 종목의 학습 구간 5분위로 나눈 값(Q1 잔잔 ~ Q5 요동). 연구 27d와 같은 정의다. 예측 시점에 이미 아는 값만 쓰므로 실시간에 그대로 옮길 수 있다. 사후 실현 RV로 나누면 예측 시점에 국면을 알 수 없으므로 쓰지 않는다.
- **경계 계산**: 2026-10-05 이전 구간에서 종목·구간(H)별로 한 번 계산해 `regime_boundaries` 테이블에 버전과 함께 저장한다. 실시간에는 이 경계를 조회만 하고 다시 계산하지 않는다. 경계를 실시간 데이터로 갱신하면 국면의 뜻이 시점마다 달라진다.
- **주의**: 15분 구간은 직전 RV의 20% 분위수가 0인 종목이 있다(27d 1-1). 가격이 멈춘 봉이 많은 종목이라 Q1 경계가 0이 되므로, 가격 정지 비율을 함께 보고한다.

## 5. 국면별 모델 라우팅 (고려 대상, MVP 비활성)

- **근거**: 27d 탐색 결과(시드 5개, 기존 평가 구간)에서 국면마다 1위 모델이 다르다. 요동 국면(Q5) 1시간~12시간은 순환 신경망(GRU·LSTM), 잔잔~보통 국면의 짧은 구간은 트리·커널 계열이 1위였다. 그런데 GARCH+LightGBM 하나가 국면×구간 25칸 중 24칸에서 1위와 통계적으로 구분되지 않았다. 그래서 라우팅으로 얻는 이득은 Q5 15분 같은 일부 칸에 몰려 있을 가능성이 크다.
- **한계**: 이 표는 결과를 본 뒤 고른 사후 선택이고, 28번(학습 절차 정비·시드 확장) 결과로 바뀔 수 있다. **(2026-10-18 S200) 27번까지 GARCH-t는 일부 종목이 arch 시작값에 고착된 비최대우도 결과였고(26c 6종목), GARCH+LightGBM은 그 GARCH 값을 입력으로 쓴다. 그래서 "GARCH+LightGBM 24/25칸 동률"은 28번(고착 수정) 결과로 다시 확인하기 전까지 근거로 쓰지 않는다.** 신경망·파운데이션·트리 단독 결과는 영향이 없다(연구 세션 인계). 연구 트랙은 라우팅 규칙을 사전 등록한 뒤 2026-10-06 이후 구간에서 확증할 계획이다(`test/process.md` 2·4단계).
- **MVP 설계**: 라우터는 자리만 만든다.
  - `routing_rules` 테이블: (규칙 버전, 국면, 구간 H, 모델 이름, 출처 실험, 등록 시각).
  - 조회 함수: (종목, 국면, H) → 모델. 규칙이 없으면 기본 지표 묶음 전체를 그대로 낸다.
  - LLM에는 국면 이름과 모든 보조 지표를 함께 넘긴다. 어느 모델을 믿을지 LLM이 고르지 않게 한다.
- **활성화 조건**: 연구 트랙의 사전 등록과 28번 결과가 나온 뒤, 등록된 규칙을 그대로 옮긴다. 서비스 쪽에서 새 규칙을 만들지 않는다.

## 6. 판단 층: 결정 모델 + LLM

### 6-1. 결정 모델이란
- 일반 LLM은 단어를 하나씩 이어 쓰는 반복으로 글을 만든다. 결정 모델은 같은 "읽는 몸통"을 쓰되, 반복 생성을 떼어내고 **미리 준 선택지에만 확률을 매기는 출구**를 단 모델이다. 한 번 읽고 끝나므로 빠르고, 출력 형식이 깨지지 않으며, 선택지별 확률을 준다. 대신 이유를 설명하지 못한다.
- 질문 유형: `choice`(하나 고르기), `noul`(참일 확률), `score`(순서 등급).

### 6-2. 후보 (2026-10-15 조사)

| :--- | :--- | :--- |
| Jev 1.13(TypeSafe), Microsoft-Decision-1, OpenAI Decisions API | 호스팅 API 전용 | 상시 판단에는 쓰지 않는다(데이터 외부 전송). 소량 대조군으로만 검토. |

### 6-3. 채택안 (0단계 시험 후 확정)
- **방식 A(기본)**: 모델 1개(Qwen3.5-4B, 4비트 Q4_K_M). ① 입력을 한 번 읽고, ② 유지/축소/관망 토큰 확률을 꺼내 판단하고, ③ 같은 모델이 이어서 근거를 쓴다. 확률은 2026-10-05 이전 기간 라벨로 온도 하나만 맞춰 보정한다(Kev와 같은 방식). 온도 보정은 크기만 고치고 순서가 틀린 판단은 고치지 못한다.
- **방식 B(비교)**: Clef-Flash로 판단, Qwen3.5-4B로 설명. 두 모델을 동시에 두지 않고 번갈아 올린다(최대 약 7.5GB). 방식 A의 판단이 보정 후에도 부족할 때만 채택한다.
- **원칙**: 설명 LLM은 판단을 바꾸지 못한다. 설명과 판단이 어긋나면 판단 로그에 "불일치"로 남긴다.
- **라벨과 기준선**: 판단을 보정·평가할 라벨 정의와, LLM이 넘어야 할 규칙 기반 기준선은 §11(초안, 사용자 확정 전)에 있다.
- **출력 스키마**: 국면, 위험 1~5, 근거 지표, 유지/축소/관망과 각 확률, 불확실성. 생성 부분은 JSON 스키마로 강제하고 사고 모드는 끈다.

## 7. 실행 환경

- **LLM 실행기**: llama.cpp 계열(llama-server 사전 빌드 배포판 또는 Ollama 사용자 영역 설치). 서버에 nvcc·cmake가 없어 소스 빌드는 하지 않는다. vLLM은 GPU 메모리를 비율로 미리 잡고 NVML이 필요해서 쓰지 않는다. 최대 메모리는 모델·문맥 길이·동시 요청 수를 고정해서 정한다.
- **상주 프로세스 위치**: 주피터 허브가 재시작되면 그 cgroup의 작업이 setsid로 띄운 것까지 모두 종료된다(2026-10-15 03:11 사건). LLM 서버와 정기 수집은 cron으로 띄워 `cron.service` 쪽에 둔다(`AGENTS.md` 2.14).
- **GPU 확인**: 시스템 `nvidia-smi`는 드라이버 불일치(모듈 595.71.05, 라이브러리 595.84)로 깨져 있다. `~/.local/bin/nvidia-smi`(사용자 영역 595.71.05 NVML)를 쓴다. 모듈 버전이 바뀌면 자동으로 시스템 것을 쓴다. 다음 부팅 커널 7.0.0-38에 NVIDIA 모듈이 없어 관리자에게 드라이버 595.99.02 설치를 요청해야 한다(루트 `history.md` 2026-10-15).
- **서비스 GPU 예산**: LLM 4.5GB 이하 + TimesFM 추론 1.5GB 이하 = 6GB(2.14의 서비스 몫 10GB 안). 올리기 전 남은 GPU가 예산 + 4GB보다 적으면 기다리거나 CPU로 돌린다.

## 9. 0단계에서 확인할 것

1. 원본 DB 읽기 전용 접속, 두 코드(`contexts/text_context.py`, `marts/historical_flow.py`)의 쓰기 경로를 `llm_agent.db`로 변경.

### 10-1. 판단 쏠림과 위치 편향 (S187)

- **마트 DB 보존(지적 7)**: `_persist`가 마트 DB를 열지 못하면 파일을 지우고 새로 만들던 복구를 없앴다. 이제 `RuntimeError`로 중단하고 파일은 그대로 둔다. 합성 시험: 손상 파일로 마트를 만들면 예외로 멈추고 파일 해시가 같다.

## 11. 판단 라벨 정의와 규칙 기반 기준선 (초안, S190, S188 지적 5, 사용자 확정 전)

> 이 절은 초안이다. 아래 "결정 필요" 항목은 사용자가 정한 뒤 확정 표시를 붙인다. 확정 전에는 라벨로 보정·평가하지 않는다.

### 11-1. 왜 필요한가

판단(유지/관망/축소)의 확률을 보정하고 잘했는지 평가하려면, 판단 시점 뒤에 실제로 어떤 판단이 맞았는지를 정하는 **라벨**이 필요하다. 지금은 라벨이 없어서 §10-1의 확률이 "그럴듯한지"만 볼 수 있고 "맞는지"는 볼 수 없다. 또 LLM 판단이 단순 규칙보다 나은지 보여 줄 **기준선**이 없으면 LLM을 쓸 근거가 없다.

### 11-2. 라벨 정의(초안)

판단 시각 t(KST, 15분 봉이 닫힌 시각), 종목 i에 대해 t 뒤 평가 기간 h 동안의 실제 결과로 정답 판단을 정한다.

| 요소 | 초안 | 결정 필요(선택지) |
| :--- | :--- | :--- |
| 평가 기간 h | 12시간(주), 4시간(보조) | 4h / 12h / 24h. 보조 지표 구간(1h·4h·12h)과 맞춘다. |
| 낙폭 dd_h | t의 종가 대비 (t, t+h] 15분 **저가** 최저치의 수익률(보수적) | 저가 / 종가 |
| 손실 한도 L_i,h | 종목·구간별 변동성 배수: L = k × (학습 구간 h 실현 변동성 중앙값), k = 2 | k = 1.5 / 2 / 3, 또는 고정 % (예: 12h 3%). 고정 %는 저유동 종목에 너무 자주 걸린다. |
| 보유 비중 | 유지 = 목표 비중 100%, 관망 = 직전 비중 유지·신규 진입 0, 축소 = 직전 비중의 50% | 축소 50% / 0%(전량), 관망을 별도 비중(예: 75%)으로 둘지 |
| 거래비용 c | 업비트 KRW 수수료 0.05%(편도) + 슬리피지(유동성 상위 5종목 0.02%, 나머지 0.10%) | 슬리피지 값, 거래대금 기반 추정으로 바꿀지 |
| 판단 주기 | 15분마다 판단, 비중 변경은 판단이 바뀔 때만 | 1시간마다로 줄일지(거래비용) |

라벨 규칙(초안):
- **축소가 정답**: dd_h ≤ −L_i,h. 줄였으면 한도를 넘는 손실을 피했다. 단 L_i,h가 왕복 비용 2c보다 커야 의미가 있다(그렇지 않은 종목·구간은 라벨에서 뺀다).
- **유지가 정답**: dd_h > −L_i,h / 2 이고 (t, t+h] 실현 변동성이 그 종목 학습 구간 60% 분위 이하.
- **관망이 정답**: 그 사이(한도는 안 넘었지만 흔들림이 컸음).
- 대안(결정 필요): 세 판단의 비용 차감 손익 U(a) = w_a × r_h − λ × w_a × max(0, −dd_h − L) − c × |Δw_a| 를 계산해 가장 큰 판단을 정답으로 두는 효용 기반 라벨. 기준이 하나로 묶이지만 λ를 정해야 한다.

주의:
- 라벨은 미래 값을 쓰므로 **보정·평가에만** 쓰고 판단 입력에는 넣지 않는다.
- 15분마다 판단하면 h = 12시간 라벨이 48개씩 겹쳐 자기상관이 생긴다. 평가 검정은 HAC 표준오차나 블록 부트스트랩을 쓴다.
- 누설 규칙: 2026-10-06 이후 구간에서 변동성 모델의 정확도·순위·검정을 계산하지 않는다. 판단 라벨 평가도 그 구간의 변동성 예측 성능을 간접적으로 드러내므로, **판단 평가 기간을 2026-10-05 이전으로 할지, 연구 확증이 끝난 뒤로 미룰지**는 사용자 결정이다. 2026-10-05 이전 평가에는 판단 시점마다 그때까지의 정보로 만든 변동성 예측(연구 29번 계획의 out-of-fold 예측)이 필요하다.
- 낙폭 기반 라벨은 하방 결과를 보지만 방향을 예측하라는 뜻이 아니다. 판단 입력에는 방향 정보(미래 수익률, 마트의 forward_return)를 넣지 않는다.

### 11-3. 규칙 기반 기준선(초안)

LLM 판단은 같은 라벨·같은 비용에서 아래 규칙보다 나아야 쓸 가치가 있다. 규칙은 모두 판단 시점에 아는 값만 쓴다.

| 이름 | 규칙 | 쓰는 값 |
| :--- | :--- | :--- |
| B0 항상 유지 | 늘 유지(비중 100%) | 없음 |
| B1 사전 국면 | 직전 RV 국면(H = 1h 또는 4h) Q5 → 축소, Q4 → 관망, 그 밖 → 유지 | `regime_boundaries` |
| B2 예측 RV 분위 | 예측 12h RV(TimesFM q50, 또는 GARCH-t)가 종목 학습 구간 분위 80% 이상 → 축소, 60~80% → 관망, 미만 → 유지 | 2단계 보조 지표 |
| B3 변동성 목표 | 목표 비중 = min(1, σ_목표 / σ̂_h)를 세 단계로 나눔(≥ 0.8 유지, 0.5~0.8 관망, < 0.5 축소). σ_목표 = 종목 학습 구간 h 변동성 중앙값 | 2단계 보조 지표 |
| B4 뉴스 악재 | 최근 6시간 종목·시장 기사 중 위험 주제(`topic_risk`) 기사가 2건 이상 → 축소, 1건 → 관망 | `load_news_as_of` |
| B5 결합 | B2와 B4 중 더 신중한 쪽 | B2·B4 |

- 비교 지표(결정 필요): 라벨 정확도·매크로 F1, 비용 차감 손익, 손실 한도 초과 횟수(축소해야 했는데 못 줄인 비율), 거래 횟수. 단일 지표 1위로 고르지 않는다.
- LLM이 B2·B3·B5를 의미 있게 넘지 못하면 LLM은 설명 생성에만 쓰고 판단은 규칙으로 하는 것이 맞다.
- 분위 경계(60·80%)와 6시간·2건 같은 값은 초안의 임의 값이다. 확정할 때 2026-10-05 이전 개발 구간에서만 고르고, 고른 뒤 평가 구간에서 바꾸지 않는다.

### 10-7. GARCH 다중 척도와 지시문 v2·v3 (S201, 2026-10-18)

- **GARCH-t 다중 척도**: 연구 28번 `garch_t_fit_robust`와 같은 규칙(×100·×1000·×10 중 수렴·비고착 해의 ×100 환산 로그우도 최대)으로 바꿨다. 03:45 기준 18종목: ×1000 10종목·×100 8종목 선택, ×100에서 고착된 BTC·MOC·STRAX·XLM·XRP는 다른 척도로 해결, 의심 0. 연구 GARCH-BIC는 20종목 중 FIGARCH-t 17·FIGARCH-skew-t 2·GARCH(1,2)-t 1을 골랐다(GARCH(1,1)-t 0). 서비스 사양 변경은 28번 결과 뒤.
- **지시문 v2**(가격 정지를 "가격 변화 없는 봉"과 "거래 없는 봉"으로 나눠 뜻 설명, 종목 기사 없음 명시) 단발 시험 3종목(하루 1회 합의분): BTC 유지 0.54·DOGE 축소 0.84·STRAX 축소 0.42, 배치 편차 0.24·0.28·0.17(v1 0.36·0.45·0.37에서 줄었다). 그런데 모델이 비율 방향을 거꾸로 읽었다: DOGE 무체결 0%를 "유동성 극단 악화", STRAX 3%를 "유동성 저하 확인"으로 썼다.
